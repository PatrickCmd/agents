01What Are Coroutines?

A coroutine is a special kind of function that can pause its execution and yield control back to the event loop, then resume right where it left off. Unlike regular functions that run start-to-finish, coroutines are cooperative — they voluntarily suspend themselves when they hit an I/O wait.

In Python, you define a coroutine with async def and pause it with await. The module that orchestrates everything is asyncio, part of the standard library since Python 3.4.

02Sync vs Async — The Core Problem

Imagine you need to fetch data from three different APIs. In synchronous code, each request blocks the program — you wait idle while the network does its thing. With async, you fire all three requests and let the event loop juggle them, doing useful work during every wait.

Diagram — Synchronous vs Asynchronous Execution Timeline
Key Insight

asyncio doesn't make individual tasks faster. It makes waiting faster by overlapping I/O-bound operations. CPU-bound work still runs on one thread.

03Your First Coroutine

Let's start simple. Define a coroutine with async def, then run it with asyncio.run().

hello_async.py 
import asyncio

async def greet(name: str) -> None:
    print(f"Hello, {name}! Starting work...")
    await asyncio.sleep(1)   # Simulate I/O — yields control for 1 second
    print(f"Done, {name}!")

# This is the entry point — boots the event loop and runs the coroutine
asyncio.run(greet("Patrick"))
▸ Output Hello, Patrick! Starting work...
Done, Patrick!
Common Mistake

Calling greet("Patrick") without await or asyncio.run() returns a coroutine object — it doesn't execute. You'll see a RuntimeWarning: coroutine was never awaited.

04The Event Loop — Engine of asyncio

The event loop is the central scheduler. It maintains a queue of coroutines. When a coroutine hits an await, it suspends, and the loop picks up the next ready task. When the awaited operation completes (network response, timer, etc.), the loop resumes that coroutine.

05await, Tasks & Concurrency

Simply await-ing coroutines one after another still runs them sequentially. To get true concurrency, you need to wrap coroutines in Tasks using asyncio.create_task().

Sequential (slow):

sequential.py 
import asyncio, time

async def fetch(name: str, delay: float) -> str:
    print(f"⏳ {name}: requesting...")
    await asyncio.sleep(delay)
    print(f"✅ {name}: done!")
    return f"{name} result"

async def main():
    t0 = time.perf_counter()

    # Sequential — each await blocks the next
    await fetch("API-1", 2)
    await fetch("API-2", 1)
    await fetch("API-3", 1.5)

    print(f"⏱  Total: {time.perf_counter() - t0:.1f}s")

asyncio.run(main())
▸ Output — Sequential ⏳ API-1: requesting...
✅ API-1: done!
⏳ API-2: requesting...
✅ API-2: done!
⏳ API-3: requesting...
✅ API-3: done!
⏱ Total: 4.5s

Concurrent (fast) — with create_task:

concurrent.py 
async def main():
    t0 = time.perf_counter()

    # Create tasks — all start immediately!
    task1 = asyncio.create_task(fetch("API-1", 2))
    task2 = asyncio.create_task(fetch("API-2", 1))
    task3 = asyncio.create_task(fetch("API-3", 1.5))

    # Await all results
    r1 = await task1
    r2 = await task2
    r3 = await task3

    print(f"⏱  Total: {time.perf_counter() - t0:.1f}s")

asyncio.run(main())
▸ Output — Concurrent ⏳ API-1: requesting...
⏳ API-2: requesting...
⏳ API-3: requesting...
✅ API-2: done!
✅ API-3: done!
✅ API-1: done!
⏱ Total: 2.0s
Why 2.0s?

All three tasks start at the same time. The longest takes 2 seconds, so the total wall-clock time is ~2s — determined by the slowest task, not the sum.

06gather() — Running Tasks in Parallel

asyncio.gather() is a convenience that wraps multiple coroutines into tasks and waits for all of them. It returns results in the same order you passed the coroutines, regardless of which finishes first.

gather_example.py 
import asyncio

async def fetch_user(user_id: int) -> dict:
    await asyncio.sleep(1)  # simulate DB lookup
    return {"id": user_id, "name": f"User_{user_id}"}

async def main():
    user_ids = [101, 102, 103, 104, 105]

    # Fire all lookups concurrently
    users = await asyncio.gather(
        *[fetch_user(uid) for uid in user_ids]
    )

    for u in users:
        print(u)

asyncio.run(main())
▸ Output (all in ~1s, not 5s) {'id': 101, 'name': 'User_101'}
{'id': 102, 'name': 'User_102'}
{'id': 103, 'name': 'User_103'}
{'id': 104, 'name': 'User_104'}
{'id': 105, 'name': 'User_105'}

07Real Patterns: Producers, Consumers & Queues

One of the most powerful asyncio patterns is the producer-consumer architecture using asyncio.Queue. Producers generate work items, and consumers process them concurrently.

producer_consumer.py 
import asyncio
import random

async def producer(queue: asyncio.Queue, name: str) -> None:
    for i in range(5):
        item = f"{name}-item-{i}"
        await asyncio.sleep(random.uniform(0.1, 0.5))
        await queue.put(item)
        print(f"📦 {name} produced: {item}")

async def consumer(queue: asyncio.Queue, name: str) -> None:
    while True:
        item = await queue.get()
        print(f"⚙️  {name} processing: {item}")
        await asyncio.sleep(random.uniform(0.2, 0.8))  # simulate work
        queue.task_done()
        print(f"✅ {name} finished: {item}")

async def main():
    queue: asyncio.Queue = asyncio.Queue(maxsize=10)

    # Start 2 producers and 3 consumers
    producers = [asyncio.create_task(producer(queue, f"P{i}")) for i in range(2)]
    consumers = [asyncio.create_task(consumer(queue, f"C{i}")) for i in range(3)]

    # Wait for producers to finish, then drain the queue
    await asyncio.gather(*producers)
    await queue.join()  # blocks until all items are processed

    # Cancel consumers (they run forever)
    for c in consumers:
        c.cancel()

    print("🎉 All work done!")

asyncio.run(main())

08Error Handling & Timeouts

Handling exceptions in tasks

By default, exceptions in tasks are swallowed until you await them. Use return_exceptions=True in gather() to collect errors without crashing.

error_handling.py 
import asyncio

async def risky_call(n: int) -> str:
    await asyncio.sleep(1)
    if n == 2:
        raise ValueError(f"Task {n} exploded!")
    return f"Task {n} OK"

async def main():
    results = await asyncio.gather(
        risky_call(1),
        risky_call(2),
        risky_call(3),
        return_exceptions=True  # Don't crash, collect errors
    )
    for r in results:
        if isinstance(r, Exception):
            print(f"❌ Error: {r}")
        else:
            print(f"✅ {r}")

asyncio.run(main())
▸ Output ✅ Task 1 OK
❌ Error: Task 2 exploded!
✅ Task 3 OK

Timeouts

Use asyncio.wait_for() to cancel a coroutine if it takes too long, or the newer asyncio.timeout() context manager (Python 3.11+).

timeout_example.py 
import asyncio

async def slow_operation() -> str:
    await asyncio.sleep(10)
    return "done"

async def main():
    # Method 1: wait_for (all Python 3.7+)
    try:
        result = await asyncio.wait_for(slow_operation(), timeout=2.0)
    except asyncio.TimeoutError:
        print("⏰ Operation timed out after 2s!")

    # Method 2: timeout context manager (Python 3.11+)
    try:
        async with asyncio.timeout(2.0):
            result = await slow_operation()
    except TimeoutError:
        print("⏰ Context-managed timeout!")

asyncio.run(main())

09Applications of Coroutines

Coroutines shine wherever your program spends time waiting rather than computing. Here are the major real-world domains:

🌐

Web Servers & APIs

Frameworks like FastAPI, Starlette, and aiohttp handle thousands of HTTP requests concurrently on a single thread using async handlers.

🕷️

Web Scraping

Crawl hundreds of pages in parallel with aiohttp or httpx. What takes minutes synchronously finishes in seconds.

💬

Chat & WebSockets

Real-time apps — chat rooms, notifications, live dashboards — rely on persistent async connections managed by the event loop.

🗄️

Database Operations

Async drivers like asyncpg, aiomysql, and motor (MongoDB) let you run thousands of queries concurrently without blocking.

📡

Microservices & APIs

Service-to-service calls are I/O-bound by nature. Async enables a single service to fan-out requests to multiple downstream APIs simultaneously.

🤖

LLM & AI Pipelines

Batch multiple model API calls concurrently. Stream tokens from ChatGPT/Claude APIs with async iterators for real-time UX.

📂

File & Network I/O

With aiofiles, read/write files without blocking. Process log streams, upload to S3, or transfer data over sockets asynchronously.

⏱️

Task Scheduling

Build cron-like schedulers, rate limiters, and background workers entirely in async Python — no Celery or Redis required for simple cases.

Example: Concurrent HTTP Requests with httpx

real_world_http.py 
import asyncio
import httpx

async def fetch_url(client: httpx.AsyncClient, url: str) -> dict:
    response = await client.get(url)
    return {"url": url, "status": response.status_code, "bytes": len(response.content)}

async def main():
    urls = [
        "https://httpbin.org/delay/1",
        "https://httpbin.org/delay/2",
        "https://httpbin.org/delay/1",
        "https://httpbin.org/get",
    ]

    async with httpx.AsyncClient() as client:
        results = await asyncio.gather(
            *[fetch_url(client, url) for url in urls]
        )

    for r in results:
        print(f"{r['status']} | {r['bytes']:>6}B | {r['url']}")

asyncio.run(main())

Example: Async FastAPI Endpoint

fastapi_async.py 
from fastapi import FastAPI
import httpx

app = FastAPI()

@app.get("/dashboard")
async def dashboard():
    async with httpx.AsyncClient() as client:
        # Fan out to 3 internal services concurrently
        users, orders, metrics = await asyncio.gather(
            client.get("http://user-svc/api/users"),
            client.get("http://order-svc/api/recent"),
            client.get("http://analytics-svc/api/kpis"),
        )
    return {
        "users": users.json(),
        "orders": orders.json(),
        "metrics": metrics.json(),
    }
This is a pattern you'll use often

The FastAPI example above is exactly how you'd build a dashboard endpoint that fetches from multiple backend services — it runs in ~max(service latencies) instead of their sum.

Quick Reference

Concept Syntax What it does
Define coroutine async def fn(): Declares a coroutine function
Pause & yield await coro() Suspends until the awaited thing completes
Run from sync asyncio.run(coro()) Creates event loop, runs coroutine, cleans up
Create task asyncio.create_task(coro()) Schedules coroutine to run concurrently
Run in parallel asyncio.gather(*coros) Runs multiple coroutines, returns ordered results
Timeout asyncio.wait_for(coro(), timeout=N) Cancels coroutine if it exceeds N seconds
Queue asyncio.Queue(maxsize=N) Async-safe FIFO for producer-consumer patterns
Sleep await asyncio.sleep(N) Non-blocking pause — yields to event loop
Semaphore asyncio.Semaphore(N) Limits concurrency to N simultaneous tasks
